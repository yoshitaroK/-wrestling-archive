# /brag — 作ったものの成果を1枚のページにまとめる

`/brag` のあとに書かれたものが、まとめる対象です(機能の名前、「今週」「10月」などの期間、PR の番号)。何も書かれていなければ、何をまとめたいかを聞いてください。
運営者は初心者です。ページも説明もすべて日本語で書きます。

## 1. 事実を集める

数字や出来事は、すべてリポジトリから数えたものだけを使います。覚えていることや推測では書きません。

1. 対象のコミットを探す:`git log --format='%h %ad %s' --date=short` を、ファイル(例:ニュースなら `news.py`・`news.json`・`articles/`・`.claude/skills/news/`)、期間(`--since`・`--until`)、言葉(`--grep`)でしぼる。`Merge pull request #N` のコミットから PR の番号を拾う。毎日の自動更新のコミット(「Update data and pages」)は数えない。
2. 各コミットの中身を `git show --stat` で見て、何を作ったか・直したかをつかむ。
3. 数字を数える。例:
   - ニュース:`news.json` の記事の数、`articles/*.md` の `[[p-` の数(選手ページへのリンク)、`event_results.csv` で足した行の数
   - 選手・大会・写真:`players.csv`・`data.json`・`photos.json` の件数、`git diff --stat <始め>..<終わり>` の増えた行
   - ビルドの状態:`build_report.json` の `errors`・`warnings`
4. 公開されているページの URL は `https://japanwrestlingchannel.com/<フォルダ>/<slug>/` の形で作る(`news/`・`events/`・`players/` など)。

## 2. ページを作る

- Artifact の決まり(`artifact-design`)に従って HTML を書き、スクラッチパッドのフォルダに置いて公開する。リポジトリの中には置かない。
- 見た目はサイトに合わせる:色は `index.html` の `:root` のトークン(黒地、アクセントの赤 `--pink`)、文字は Noto Sans JP、数字は Teko。白テーマのときの色も用意する。ニュースの記事を見せるときは、サイトのニュースと同じ白い紙面のカードにする。ロゴのピンク `--brand-pink` は使わない。
- 並べ方の手本(最初に作った「ニュース機能の成果」):
  1. 見出し:何ができるようになったかを1文で。その下に、期間と作ったものの短い説明
  2. 数字を4つまで(件数・本数など、本当に意味のあるものだけ)
  3. 作ったもの:機能ごとのカード。関係するファイル名を添える
  4. 手順があるものは流れ図(順番に意味があるときだけ番号を付ける)
  5. 公開したページ:サイトへのリンク
  6. 守った決まり(あれば)
  7. 日付ごとの流れの表:PR へのリンク(`https://github.com/yoshitaroK/-wrestling-archive/pull/N`)
  8. いちばん下に、数字をいつ・どのファイルから数えたか
- 選手の名前を出すときは、記事やサイトにすでに載っている範囲だけにする。高校生などの未成年を目立たせない。

## 3. 渡す

- 運営者にページのリンクと、何をまとめたかを短く伝える。数字の数え方で気をつけること(重ねて数えている、など)があれば書く。
- ページは最初は運営者だけが見られる。ほかの人に見せるときは、ページの共有メニューから共有することを伝える。
- リポジトリのファイルは変えないので、コミットも PR も出さない。
